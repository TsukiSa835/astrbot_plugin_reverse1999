# 重返未来：1999 助手

面向《重返未来：1999》的 AstrBot 插件，以玩家角色 Box、账号绑定和角色资源索引为开发起点，逐步扩展数据查询与展示能力。

**当前版本：0.1.0，处于早期开发阶段。账号绑定已实现持久化，Box 和皮肤查询仍使用模拟数据并返回文本。真实游戏数据接入、图片 Box、抽卡统计和攻略辅助尚未实现。**

## 功能状态

| 功能 | 当前状态 |
| --- | --- |
| 插件加载与测试指令 | 已实现 |
| Box 文字展示 | 已实现，使用模拟玩家数据；置顶角色优先显示 |
| 角色信息展示 | 等级、洞悉、塑造、共鸣、信任度、置顶、当前皮肤与心相；共鸣达到 10 级才展示调频 |
| 拥有皮肤列表 | 已实现文本展示，区分拥有列表与当前装扮 |
| 账号绑定、查询与解绑 | 已实现 SQLite 持久化，支持多账号及多人绑定同一账号 |
| 跨群聊／私聊共用绑定 | 按平台类型与发送者标识识别；适用范围见[账号绑定规范](docs/account-bindings.md) |
| 静态角色图鉴 | 已实现离线导入、只读查询和人工映射校正；尚未接入 Bot 指令 |
| 稀有度与灵感 | 图鉴已支持，灵感允许多个值；当前 Box 文本未显示灵感 |
| 图片 Box 与缺图回退 | 已有设计约定，尚未实现渲染与图片发送 |
| 真实 UID 数据查询、技能资料、语音／动画查询 | 未实现 |
| 抽卡统计、攻略及个性化养成建议 | 长期规划 |
| 网页、微信小程序 | 扩展方向，尚无对应客户端或服务接口 |

保存 UID 只建立聊天账号与游戏账号标识的关联，不验证游戏账号存在、归属或访问权限。

## 安装与快速体验

### 环境

- 已部署并能够正常收发消息的 AstrBot。
- 插件代码使用 Python 3.10+ 语法；实际运行环境还需满足所用 AstrBot 版本的要求。
- 插件使用 `StarTools.get_data_dir` 等 AstrBot 接口；目前未声明或验证完整的版本兼容范围。
- 现有文本指令无需下载美术资源。离线图鉴导入和图鉴测试需要 Pillow，使用时应安装到实际运行工具的 Python 环境。

### 安装插件

可通过 AstrBot 的仓库安装功能填写：

```text
https://github.com/TsukiSa835/astrbot_plugin_reverse1999
```

也可手动将仓库放入 AstrBot 的 `data/plugins/astrbot_plugin_reverse1999` 目录。以下命令应在 **AstrBot 根目录**执行，且目标目录尚不存在：

```bash
git clone https://github.com/TsukiSa835/astrbot_plugin_reverse1999.git data/plugins/astrbot_plugin_reverse1999
```

通过 AstrBot 插件管理重新加载插件，或重启 AstrBot，然后发送：

```text
/1999测试
/1999box player-a
/1999皮肤 player-a
```

测试绑定流程：

```text
/1999绑定 player-a
/1999box
/1999账号
```

当前模拟标识为 `player-a`（别名 `mock-player`）、`player-b` 和 `player-empty`。后者表示已找到玩家但没有角色；其他标识会提示未找到模拟玩家。输入真实 UID 不会获得真实游戏数据。

插件启动时在 AstrBot 专用插件数据目录创建 `bindings.sqlite3`。图鉴数据库需要通过独立工具生成，不会随插件启动自动创建。安装包不包含数据库、美术资源包或角色资料快照。

## 指令

表中的方括号表示可选参数，实际发送时不要输入方括号。

| 指令 | 功能 |
| --- | --- |
| `/1999测试` | 检查插件是否正常加载 |
| `/1999box [账号标识]` | 展示模拟玩家的角色 Box 文本 |
| `/1999皮肤 [账号标识]` | 展示模拟玩家拥有的皮肤与当前装扮 |
| `/1999绑定 账号标识` | 为当前聊天账号新增绑定，重复绑定不会增加记录 |
| `/1999账号` | 查看当前聊天账号的绑定列表 |
| `/1999解绑 账号标识` | 删除当前聊天账号与该账号的关联，不影响其他人的绑定 |

省略查询账号时：未绑定则提示绑定；仅绑定一个账号则自动使用；绑定多个账号则列出完整查询指令，由调用者重新发送选定的指令。显式指定账号不要求先绑定，也不会写入默认账号。

## 项目架构

设计原则是让易于变化的框架、数据来源和存储实现依赖稳定的业务模型与接口。

```text
main.py          AstrBot 指令入口与依赖组装
  ├─ services/   Box 查询、排序与账号选择规则
  ├─ presentation/  文本排版
  ├─ data_sources/  当前为模拟 Box 数据源
  └─ storage/    SQLite 绑定存储与图鉴查询
         ↓
domain/          数据模型及 Protocol 接口

tools/           独立运行的离线图鉴导入工具
data/            人工核对的素材映射规则
tests/           账号绑定与图鉴回归测试
docs/            技术规范、计划与开发记录
```

玩家养成状态与公共角色资料分别建模；绑定库与图鉴库分离；图鉴保存图片相对路径，不包含图片二进制。平台事件在入口处转换为普通业务对象，方便以后复用到其他客户端。详细边界见[架构与数据模型](docs/architecture.md)。

## 开发计划

1. 使用少量真实角色素材和模拟养成数据生成本地 Box 预览，验证卡片布局与完整立绘的显示效果。
2. 实现当前皮肤、同角色默认皮肤、占位图的回退流程，再接入 Bot 图片发送。
3. 接入可验证的真实游戏数据源，明确授权与访问边界；按需要设计共享数据缓存。
4. 扩展静态资源查询，完成敌人 Q 版素材分类；语音与动画功能开发前核对资源及运行时依赖。
5. 在数据与展示流程稳定后，评估抽卡统计、攻略辅助和其他客户端。

各阶段没有承诺发布日期。资源相关事项见[美术资源计划](docs/art-resources-todo.md)。

## 开发与验证

在插件仓库根目录、具备 Pillow 的 Python 环境中执行：

```bash
python -m unittest discover -s tests -v
```

现有 17 项测试覆盖账号绑定和图鉴导入／查询。测试使用临时数据库，不等同于 QQ 端的完整集成验证。仅调整文档时，优先检查功能描述、Markdown 与链接。

提交功能变更时，请注明实现范围、验证方式以及是否需要更新数据快照。缺图或错图反馈应尽量附角色 ID、皮肤 ID、图片相对路径与资料版本，便于复现。

## 作者与开发方式

项目由 **TsukiSa835** 发起并主导，负责需求定义、架构方向与模块边界、功能优先级、游戏业务规则和素材辨认，并通过实际使用验证推动修正。例如，多账号绑定的交互方式、当前装扮与拥有皮肤的区分、主立绘与补充素材的选择，均由项目维护者作出产品与业务判断。
