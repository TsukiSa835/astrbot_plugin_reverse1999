# 图片回退设计

状态：设计约定，尚未实现图片渲染与 Bot 图片发送。现有图鉴的缺图报告与人工忽略规则不等于运行时回退。

## 选图顺序

1. 根据角色 ID 与 `equipped_skin.skin_id` 查询当前装扮的主立绘（`portrait`）。
2. 当前装扮未知或图片读取失败时，尝试同角色的默认皮肤主立绘。
3. 默认皮肤未知或图片也不可用时，使用占位图并保留文字信息。

默认皮肤必须有可核对的归属，不能借用其他角色素材。补充立绘与装饰分件不自动替代主图。实际绘制需验证缩放、裁切及人物清晰度。

## 提示与状态保持

| 情况 | 展示要求 |
| --- | --- |
| 当前皮肤未知 | 使用默认外观并提示“当前皮肤未知，暂用默认外观” |
| 当前皮肤已知但图片失败 | 保留当前皮肤名称，提示“皮肤图片加载失败，暂用默认外观” |
| 默认图也不可用 | 使用占位图，提示图片暂不可用，保留角色文字 |
| 多个角色回退 | 可在图片底部集中列出简短提示 |

回退只影响展示，不修改 `equipped_skin`、`owned_skins` 或其他玩家状态。

## 异常处理与职责

- 日志记录失败的角色 ID、皮肤 ID 和原因；普通的数据未知不作为异常报错。
- 入库时能够解码不保证运行时文件仍可用，渲染端仍须处理文件丢失、移动和损坏。
- 图鉴查询无记录返回 `None`，数据库打开失败则抛出异常；两者应分开处理。
- 图片加载和回退在展示流程中完成，默认图片定位及占位图资源将在图片接入阶段实现。domain 不依赖文件系统或图片处理库。
