# 开发记录

本文件保留阶段成果、决策演进与历史验证；当前行为以 [README](../README.md) 和各技术规范为准。历史测试结果不代表后续版本或所有平台均已验证。

## 初始阶段

- 建立 AstrBot 插件入口、元数据与 `/1999测试`，完成早期本地加载及 QQ 群聊／私聊试用。
- 采用稳定业务模型与接口、外部适配依赖 domain 的方向，优先完成模拟数据流程，再接入真实游戏数据。
- 初始提交之后增加按玩家标识查询的模拟 Box。元数据版本仍为 `0.1.0`。

## 模拟 Box 与账号绑定

- 拆分公共角色资料和玩家养成，补充共鸣、调频、塑造、信任度、当前心相、当前装扮、拥有皮肤与置顶状态。
- 明确未知、未装备和空列表的不同语义；共鸣不足 10 级不显示调频。
- 将文字排版拆至 presentation，BoxService 执行置顶优先的稳定排序。
- 实现以平台类型和发送者标识为键的持久化绑定，支持多对多关联，排除群聊／私聊会话 ID。
- 多账号采用重新发送完整查询指令的方式，不实现待选会话，也不保存隐式默认账号。
- 历史记录包含真实指令参数解析、跨群私聊、插件重建及独立进程读取的开发环境检查；现有 7 项绑定单元测试覆盖存储与选择规则。平台收发行为仍需在实际部署中验证。

### 皮肤立绘映射冲突

    开发过程中对下载到的游戏美术资源进行逐一映射后发现部分皮肤或部分立绘互相不被映射到的问题。即存在皮肤未被映射到的立绘（4），也存在立绘未被映射到的皮肤（4），最后是29张q版未映射q版局内立绘。

- “诗的礼赞”皮肤存在重复。初次映射皮肤 ID 为 `302306`，将 `302305.png` 归为同皮肤的补充图，不创建重复皮肤。
- “恶之果”先以人物分件 `310003_3.png` 作为主图；最终决定恢复完整组合图 `310003.png`，同时将两个装饰分件和人物分件全部关联为补充图片，以保留完整构图及后续布局选择。
- `302902`、`30660001`、`30880001`、`999801` 的缺图暂时忽略；废案或占位仅为候选解释，不作为官方结论，不删除原皮肤记录。
- 29 张原未映射 Q 版图片归类为敌人局内素材，具体敌人名称及其他敌人素材分布留待核对。

校正以独立规则文件叠加到原始数据，导入记录保留规则与校验值。详细路径及最终选择集中维护于[静态图鉴规范](static-catalog.md)与[人工规则](../data/catalog_overrides.json)。

## 2026-10-10至10-19：静态展示与授权数据双线推进（0.8.0）

维护者先明确默认Box目标与分层边界，持续提出并验收卡片、星级/收集率、满收集效果、当前装备皮肤、三角色签名与主线进度设计。静态原型迭代到v13后，转向真实数据适配和长图生成。关键规则与按阶段变化见[Box开发里程碑](box-development.md)。

两条主线分别为静态Box规划与渲染、动态玩家数据获取。动态线早期尝试TapTap战绩，但因可获取字段不足而放弃，随后经界面小样本验证推进到正常会话结构化读取，并验证模拟器关闭后的独立授权读取。当前获取路径不依赖TapTap，两条主线已汇合完成本人真实Box展示。维护者本人完成必要授权、手机重登和实际在线反馈，实测成功读取会影响手机在线状态，进而确定查看快照与主动刷新分离、结束关闭连接、失败不发布半份数据的方向。完整证据边界见[玩家数据研究](player-data-research.md)。

10月18日14:48的新快照包含84位角色、672条含材料仓库记录；修正旧快照导致的等级/皮肤/道具显示滞后，形成开发者本人真实Box。10月19日完成目录统计、衣着总览、50字签名留位、双语标题、底部来源和作者信息等收尾。注册时间含义由维护者确认，个性签名正文尚待后续采集。独立工具29项测试和浏览器布局检查通过，不与正式仓库历史17项测试混算。

版本由0.1.0更新为0.8.0，表示初版集成前里程碑；本次提交范围仅文档、版本元数据、脱敏成果图与验证摘要，未将独立脚本迁入正式插件。未宣布1.0或完成QQ端真实图片验收；尚未验证长期授权或渠道服。
